# Polhem.Chat 0.1.1 — Release Notes

[繁體中文](../../zh-TW/changelogs/0.1.1.md)

This file holds the details behind the `[0.1.1]` entry in [CHANGELOG.md](../../../CHANGELOG.md).

This release came out of the first application to move onto the packages, which showed what a long, tool-heavy
conversation needs. The conversation now shows what is written for the user, and one live line under it tells what the
model is doing: what it works on, for how long, which request it is on and how many tokens it has written. Each turn's
summary adds the requests it sent and the cached part of its input. The view also keeps following the newest entry in
two cases where it used to stop.

No public member is removed or changed. Two defaults change what a conversation looks like.

What each kind of application has to act on:

- **Applications that rely on reasoning or tool calls showing as entries**: [Reasoning and tool calls show on the
  activity line](#reasoning-and-tool-calls-show-on-the-activity-line).
- **Applications that restyle the copy button**: [The copy button is an icon](#the-copy-button-is-an-icon).
- **Applications that run their own loop and send several requests a turn**: call `ChatTurn.BeginCall` before each
  request to have them counted ([Requests, cached tokens and running time](#requests-cached-tokens-and-running-time)).

## New features and changes

### The activity line

While a turn runs, one line under the conversation shows that the model is at work: an animated icon, what it is doing
(*Thinking…*, or the title of the tool it runs), the running time ("2m 32s"), the request it is on and the output
tokens reported so far. Before the first text arrives, and between a tool's result and the next response, the line
tells that a reply is on its way. It follows `IsGenerating`, so it works with a `ChatRunner` and for an application
that runs its own loop.

`ChatView.ActivityIcon` takes another animated GIF. The package decodes and plays GIFs itself, with no further
dependency. `ChatViewStrings` has the new `CallFormat`, `SecondsFormat`, `MinutesFormat` and `OutputTokensFormat`
texts.

### Requests, cached tokens and running time

Each turn's summary names the requests the turn sent when there were several, and the cached part of the input tokens
when the provider reported one (`UsageDetails.CachedInputTokenCount`), with the `CallsFormat` and `CachedTokensFormat`
texts. A turn of a single request shows no count.

`ChatRunner` counts the requests of a turn itself, from the response ids of the streamed updates. An application that
runs its own loop calls the new `ChatTurn.BeginCall` before each request. Also new: `ChatTurn.Calls`,
`ChatTurn.Elapsed`, `TurnSummaryEntry.Calls`, and change notification of `ChatConversation.CurrentTurn` and
`ChatTurn.Calls`. The count is kept in the saved history, so `LoadHistory` restores it.

## Changes in behaviour

### Reasoning and tool calls show on the activity line

The model's reasoning and its tool calls no longer show as entries. The entries stay in the conversation and its
history; only the view leaves them out. `ChatView.ShowsActivity`, or the › at the end of the activity line, shows them
again.

An application that wants the 0.1.0 look sets the property:

```xml
<chat:ChatView ShowsActivity="True" />
```

### The copy button is an icon

A reply's copy button is a small icon that shows while the pointer is over the reply, instead of a labeled button under
every reply. `ChatView.CopyCommand` is unchanged, so an application that replaces the reply template binds the same
command.

## Fixes

- `ChatView` no longer stops following the newest entry when a control far up brings itself into view, as when a
  button of a card that just closed hands its keyboard focus on. Only the user's own scrolling (wheel, scroll bar,
  keyboard, touch) leaves the end now ([#14](https://github.com/polhem-dev/polhem-chat/pull/14)).
- `ChatView` no longer stops following the newest entry when entries arrive while it grows taller, such as when a line
  under it goes away at the end of a turn. It took the offset the layout moved for the user scrolling up, and showed
  Jump to latest ([#14](https://github.com/polhem-dev/polhem-chat/pull/14)).
