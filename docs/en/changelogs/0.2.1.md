# Polhem.Chat 0.2.1 — Release Notes

[繁體中文](../../zh-TW/changelogs/0.2.1.md)

This file holds the details behind the `[0.2.1]` entry in [CHANGELOG.md](../../../CHANGELOG.md).

This release changes how the view's jump-to-latest button looks. No public member is added, removed or changed, and
`Polhem.Chat` is the same as in 0.2.0.

What each kind of application has to act on:

- **Applications that find the button by its text**, in UI tests or automation:
  [The button shows no text](#the-button-shows-no-text).
- **Applications that set their own colours**: [Two new theme resources](#two-new-theme-resources).

## New features and changes

### An icon for jump to latest

The button that appears when the user scrolls up was a text button, easy to miss over the conversation. It is now a round
button with a light shadow, floating over the end of the conversation:

- While nothing is arriving, it shows an arrow down.
- While a reply is in progress, it shows three dots that pulse one after the other, so it also says that new text is
  arriving below.

The dots pulse only while the button shows. A click still scrolls to the end and follows new text again.

### Two new theme resources

Like the package's other colours, each has a light and a dark value, and an application changes one by declaring the
same key in its own resources:

| Resource | What it colours |
|----------|-----------------|
| `PolhemChatScrollButtonBackground` | The button, nearly opaque, because it floats over the text |
| `PolhemChatScrollButtonDotBrush` | The pulsing dots, coral by default |

## Changes in behaviour

### The button shows no text

`ChatViewStrings.JumpToLatest` is now the button's tooltip and its accessible name (`AutomationProperties.Name`), not its
content, so screen readers still announce it.

**What to do**: a UI test or an automation that looked for the button by the text it shows looks for its accessible
name, or for the template part `PART_ScrollToLatest`, instead.

A control template of the application's own for `ChatView` keeps whatever button it declares: the view finds no part of
the new button by name.
