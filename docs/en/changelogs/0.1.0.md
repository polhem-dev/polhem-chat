# Polhem.Chat 0.1.0 — Release Notes

[繁體中文](../../zh-TW/changelogs/0.1.0.md)

This file holds the details behind the `[0.1.0]` entry in [CHANGELOG.md](../../../CHANGELOG.md).

The first release of two packages: `Polhem.Chat`, a conversation model that turns the streamed updates of any
`IChatClient` from Microsoft.Extensions.AI into entries a user interface shows, and `Polhem.Chat.Avalonia`, the
`ChatView` control that shows such a conversation and takes prompts. The model has no user interface dependency, so
the control is one way to show it and not the only one.

What each kind of application has to act on:

- **Every application**: nothing; this is the first release.

## New features and changes

### The conversation model (`Polhem.Chat`)

`ChatConversation` keeps two things side by side: the history sent to the model, as Microsoft.Extensions.AI
`ChatMessage`s, and the entries a user interface shows. The built-in entry types are `UserPromptEntry`,
`AssistantReplyEntry`, `ReasoningEntry`, `ToolCallEntry`, `TurnSummaryEntry` and `ErrorEntry`; an application adds
entry types of its own by deriving from `ChatEntry`. `DescribeToolCall` supplies the title a tool call shows.

`ChatTurn` turns streamed `ChatResponseUpdate`s into entries as they arrive: text, reasoning, tool calls and their
results, usage and errors. An application that runs its own loop uses it directly: `AddUserPrompt`, `BeginTurn`,
`Apply` for each update, and `Complete`, `Stop` or `Fail` to end the turn.

`ChatRunner` runs a conversation against any `IChatClient`: it sends the prompt, streams the reply, stops on request,
and measures the time and tokens of each turn. `MessageSending` can rewrite or cancel a prompt before it is sent, and
`ResponseReceived` reports each turn's result. For tool calls, wrap the client with `UseFunctionInvocation()` and pass
the tools in `ChatRunner.Options`. A provider's exception does not escape `SendAsync`: it ends the turn, is kept in
`ChatTurnResult.Exception` and shows as an `ErrorEntry`.

`SaveHistory` and `LoadHistory` keep and restore a conversation. Each turn's time and tokens are stored with the turn's
last assistant message, so the summaries come back, and they are removed before the history is sent to the model.

The package depends on `Microsoft.Extensions.AI.Abstractions` 10.4.0 or later.

### The `ChatView` control (`Polhem.Chat.Avalonia`)

`ChatView` shows a conversation in one of two ways. With `Runner` set, the control sends and stops through the
`ChatRunner`. With only `Conversation` set, it shows the conversation, raises `PromptSubmitted` and `StopRequested`,
and leaves `IsGenerating` to the application.

Each entry type has a default template, and replies render as Markdown through `Polhem.Markdown.Avalonia`. A
`DataTemplate` the application registers, on the control or higher up, takes precedence over the built-in one, so an
application can add entry types or restyle the built-in ones.

`ChatPromptBox` sends on Enter and starts a new line on Shift+Enter, and it ignores the Enter that confirms an input
method's composition. Esc or the stop button stops a reply and keeps what arrived. A finished reply copies its Markdown.
The view follows new text until the user scrolls up, then offers Jump to latest. `Suggestions` lists prompts to start
with while the conversation is empty.

`ChatViewStrings` ships English and Traditional Chinese texts and can be replaced. `ChatTheme`, added after the base
theme, works on Fluent and Semi, light and dark; its colors are `PolhemChat*` resources that an application can
redefine.

The package depends on `Polhem.Chat`, Avalonia 12.0.0 or later and `Polhem.Markdown.Avalonia` 0.1.0 or later.
