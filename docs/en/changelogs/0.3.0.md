# Polhem.Chat 0.3.0 — Release Notes

[繁體中文](../../zh-TW/changelogs/0.3.0.md)

This file holds the details behind the `[0.3.0]` entry in [CHANGELOG.md](../../../CHANGELOG.md).

What each kind of application has to act on:

- **Applications that change the view's texts**: [The view's texts moved to `Polhem.Chat`](#the-views-texts-moved-to-polhemchat).
- **Applications that handle `PromptSubmitted` or `AttachmentRejected`**: [The view's event arguments moved to
  `Polhem.Chat`](#the-views-event-arguments-moved-to-polhemchat).

## New features and changes

### `ChatComposer`

What the user does with a chat view, apart from drawing it, is now `ChatComposer` in `Polhem.Chat`: the prompt box and
the files attached to it, submitting, stopping, regenerating and editing the last prompt, and approving or rejecting tool
calls. `ChatView` keeps its properties, commands and events and does all of this through a composer of its own; its
tests pass unchanged. A view for another UI framework uses the same composer instead of doing it again.

- It works with a `ChatRunner`, or with a `ChatConversation` the application drives itself, like the view.
- It follows the runner and the conversation only between `Connect` and `Disconnect`. A view connects it while it is
  shown and disconnects it when it closes, so a runner that outlives the view holds no handler of it.
- `AddAttachmentAsync` takes the name, the size or a function that reads it, and a function that opens the file, so each
  framework passes its own file type; the checks of `ChatAttachmentLimits` are the same.

### `ChatPicturePreview`

`ChatPicturePreview` reads the size of a PNG, JPEG, GIF or WebP picture from its header and tells whether it is small
enough to preview (`MaxPixels`, `MaxAspectRatio`, `MaxFileSize`). A file of a few kilobytes can declare a picture that
takes gigabytes to decode, and an attachment may come from a loaded history that `ChatAttachmentLimits` never checked.
The Avalonia view checks each attachment with it before it decodes a preview; a template of the application's own that
shows attachments should check them the same way.

### A name for the activity toggle

`ChatStrings.ShowActivity` ("Show reasoning and tool calls") is the tooltip and accessible name of the toggle on the
activity line that shows the model's reasoning and tool calls. The Avalonia view's toggle had neither, so a screen reader
announced it only as its glyph.

## Changes in behaviour

### The view's texts moved to `Polhem.Chat`

`ChatViewStrings` is now `ChatStrings`, in the `Polhem.Chat` package and namespace, so that views on other UI frameworks
can use the same texts and translations. Its members are the same, and `ChatView.Strings` takes the new type.

- Replace `ChatViewStrings` with `ChatStrings`, and add `using Polhem.Chat;` where the file has only
  `using Polhem.Chat.Avalonia;`.
- A subclass that overrides a formatting method keeps working once renamed.

`ChatStrings` also formats what the default templates showed through their own converters: `DescribeTurn` writes the
summary line of a turn, and `DescribeToolStatus` the word for the state of a tool call. Both are virtual, so an
application changes them the way it changes the other formats.

`VisibleText` is public in `Polhem.Chat`. It escapes the characters that draw nothing or reorder the text around them,
so that what the user reads is what a tool receives; a template of the application's own that shows tool arguments,
tool results or file names should show them through it.

### Fewer pictures get a preview

The check that decides whether an attached picture gets a preview is stricter, in the Avalonia view as in the new
Blazor one:

- A GIF counts each of its frames, not only the logical screen its header declares. A GIF of a few dozen bytes can
  declare a small screen and a frame of 20000 × 20000 pixels, which a decoder enlarges the picture to. Such a GIF now
  shows as its name.
- A picture of more than 5 MB (`ChatPicturePreview.MaxFileSize`) shows as its name. A small picture can be followed by
  any amount of data, and a web view hands the whole file to the browser.

### The view's event arguments moved to `Polhem.Chat`

`PromptSubmittedEventArgs` and `ChatAttachmentRejectedEventArgs` moved from `Polhem.Chat.Avalonia` to `Polhem.Chat`, since
`ChatComposer` raises them too. Their members are unchanged, and `ChatView.PromptSubmitted` and
`ChatView.AttachmentRejected` take them as before. Add `using Polhem.Chat;` where a file names them and has only
`using Polhem.Chat.Avalonia;`.
