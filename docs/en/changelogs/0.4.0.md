# Polhem.Chat 0.4.0 — Release Notes

[繁體中文](../../zh-TW/changelogs/0.4.0.md)

This file holds the details behind the `[0.4.0]` entry in [CHANGELOG.md](../../../CHANGELOG.md).

What each kind of application has to act on:

- **Applications that reference a Polhem.Markdown package themselves**: [The Markdown viewers move to
  0.5.0](#the-markdown-viewers-move-to-050).

Everything else in this version adds API; an application that uses none of it behaves as before.

## New features

### Context sent with a prompt

`PromptContext` is text sent with a prompt that the user did not type, such as the selected text of a document, with a
label that names it. A `MessageSending` handler adds it to `MessageSendingEventArgs.Context`:

```csharp
runner.MessageSending += (_, e) =>
{
    if (!e.ReplacesLastPrompt)
        e.Context.Add(new PromptContext("Selection", selectedText));
};
```

- **What the model receives.** The prompt stays one user message with one text block: each item as
  `<context label="…">…</context>`, then the prompt's text, then the files. A request with context needs nothing a
  provider might reject. The label is escaped so it cannot close its attribute.
- **What the views show.** Both views show each item as a chip with its label next to the prompt's files, never its
  text. There is no chip to remove before sending: what goes with a prompt is the host's decision, made in its own UI.
- **History.** Each item is stored as a `TextContent` before the prompt's text, with its label in
  `AdditionalProperties["polhem.chat.contextLabel"]`, so `SaveHistory` and `LoadHistory` keep it and a history saved
  by an earlier version loads as before. `ChatMessage.Text` of such a prompt includes the context's text.
- **Regenerate and edit.** When `ReplacesLastPrompt` is true, `Context` already holds the last prompt's context, so a
  handler that adds context only when it is false sends it exactly once; a handler may also remove or replace it.
- `UserPromptEntry.Context` holds a prompt's context, and `ChatConversation.AddUserPrompt` takes it for an application
  that drives the conversation itself.

### Slash commands in the prompt box

`Commands` on both views (and on `ChatComposer`) takes the `PromptCommand` items a host offers. Typing `/` at the start
of the box lists the commands whose name matches, those that start with the typed text first, ignoring case.

- ↑ and ↓ move the selection, Enter chooses it, Esc closes the list before it would stop a reply or end an edit, and a
  click chooses a command and leaves the focus in the box. While an input method composes, these keys stay with it.
- A command fills the box with its text for the user to finish, or sends at once when `SendsImmediately` is set. While a
  reply is in progress, a send-at-once command goes into the box instead, so the choice is not lost.
- A screen reader announces the selected command through a polite live region; `ChatStrings.Commands`,
  `CommandFormat` and `FormatCommand` set what it hears, in English and Traditional Chinese. The Blazor list is a
  `listbox` tied to the box with `aria-activedescendant`.
- The host can replace the list at any time, and a list that raises `INotifyCollectionChanged` is followed while the
  view is shown.
- Without `Commands`, a slash is plain text and the keys behave as before.

A command carries text only, not context or chat options; a `MessageSending` handler can add either from the prompt's
text.

## Changes in behaviour

### The Markdown viewers move to 0.5.0

The Avalonia control takes `Polhem.Markdown.Avalonia` 0.5.0 and the Blazor component `Polhem.Markdown.Blazor` 0.5.0,
up from 0.4.1. Both pin `Polhem.Markdown` to that exact version. 0.5.0 adds features, mostly to the Avalonia editor;
the viewers the chat views use show replies as before. What it added is in the
[Polhem.Markdown changelog](https://github.com/polhem-dev/polhem-markdown/blob/main/CHANGELOG.md).

An application that references `Polhem.Markdown`, `Polhem.Markdown.Avalonia` or `Polhem.Markdown.Blazor` itself moves
its reference to 0.5.0; otherwise NuGet reports the two versions as a conflict.
