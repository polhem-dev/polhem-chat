## 新功能

### 隨提問送出的上下文

`PromptContext` 是隨提問一起送出、但不是使用者打的文字，例如文件中選取的文字，並帶一個說明它是什麼的標籤。
由 `MessageSending` 的處理常式加進 `MessageSendingEventArgs.Context`：

```csharp
runner.MessageSending += (_, e) =>
{
    if (!e.ReplacesLastPrompt)
        e.Context.Add(new PromptContext("Selection", selectedText));
};
```

- **模型收到什麼。** 提問仍是一則 user message、一個文字區塊：每一項包成 `<context label="…">…</context>`，
  接著是提問文字，再來是檔案。帶上下文的請求不需要任何 provider 可能拒絕的格式。標籤會被跳脫，無法提前結束屬性。
- **view 顯示什麼。** 兩個 view 都在提問的檔案旁，以 chip 顯示每一項的標籤，不顯示內容。送出前沒有可移除的 chip：
  要附上什麼由宿主在自己的 UI 決定。
- **歷史紀錄。** 每一項存成提問文字之前的 `TextContent`，標籤放在
  `AdditionalProperties["polhem.chat.contextLabel"]`，所以 `SaveHistory` 與 `LoadHistory` 會保存它，
  舊版存下的歷史紀錄也照常載入。帶上下文的提問，其 `ChatMessage.Text` 會包含上下文的文字。
- **重新生成與編輯。** `ReplacesLastPrompt` 為 true 時，`Context` 已預先帶入上一則提問的上下文，
  所以只在它為 false 時才加入的處理常式只會送出一次；處理常式也可以移除或替換它。
- `UserPromptEntry.Context` 存放提問的上下文；自己驅動對話的應用程式可用 `ChatConversation.AddUserPrompt` 傳入。

### 輸入框的 / 指令

兩個 view（以及 `ChatComposer`）的 `Commands` 接收宿主提供的 `PromptCommand`。在輸入框開頭打 `/`，
會列出名稱相符的指令，以輸入文字開頭的排在前面，不分大小寫。

- ↑ 與 ↓ 移動選取，Enter 選定，Esc 關閉清單（優先於停止回覆或結束編輯），點選指令後焦點仍留在輸入框。
  輸入法組字時，這些按鍵交給輸入法。
- 指令會把文字填進輸入框讓使用者接著寫；設定 `SendsImmediately` 則立刻送出。回覆進行中時，
  立刻送出的指令改為填進輸入框，選擇不會遺失。
- 螢幕閱讀器透過 polite live region 念出目前選取的指令；念的內容由 `ChatStrings.Commands`、`CommandFormat`
  與 `FormatCommand` 決定，提供英文與繁體中文。Blazor 的清單是以 `aria-activedescendant` 連到輸入框的 `listbox`。
- 宿主可以隨時更換清單；會觸發 `INotifyCollectionChanged` 的清單，在 view 顯示期間會被追蹤。
- 沒有設定 `Commands` 時，斜線就是一般文字，按鍵行為不變。

指令只帶文字，不帶上下文或 chat options；需要時可在 `MessageSending` 的處理常式中依提問文字加入。

## 行為變更

### Markdown 檢視器升到 0.5.0

Avalonia 控制項改用 `Polhem.Markdown.Avalonia` 0.5.0，Blazor 元件改用 `Polhem.Markdown.Blazor` 0.5.0，
原本是 0.4.1。兩者都把 `Polhem.Markdown` 鎖定在同一個版本。0.5.0 新增的功能主要在 Avalonia 編輯器，
chat view 所用的檢視器呈現回覆的方式不變。新增內容見
[Polhem.Markdown 的變更紀錄](https://github.com/polhem-dev/polhem-markdown/blob/main/CHANGELOG.md)。

自行引用 `Polhem.Markdown`、`Polhem.Markdown.Avalonia` 或 `Polhem.Markdown.Blazor` 的應用程式，要把引用升到 0.5.0，
否則 NuGet 會回報兩個版本衝突。
