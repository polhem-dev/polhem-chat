## 新功能與變更

### 工具呼叫核准

以 `ApprovalRequiredAIFunction` 包裝的工具，要使用者核准後才會執行。`FunctionInvokingChatClient` 不會執行這種工具，
而是送出 `ToolApprovalRequestContent` 並結束串流。這個呼叫會顯示成等待使用者決定的卡片，上面有「核准」與「拒絕」鈕，
對話下方的進度列也會說明正在等待核准。不論 `ChatView.ShowsActivity` 怎麼設，這張卡片都會顯示。使用者決定完所有等待中的
呼叫後，`ChatRunner` 送出決定、該輪繼續：核准的呼叫會執行並完成，拒絕的呼叫顯示為已拒絕，模型也會知道。

- 沒按下按鈕就不會執行：沒有預設按鈕、沒有逾時，也沒有「全部核准」。
- 呼叫等待中時停止該輪（停止鈕、Esc 或 runner 的取消權杖）即視為拒絕。該輪以其他方式結束時也一樣拒絕，拒絕會記進歷史，
  之後的要求不會執行它。
- 使用者已核准、但該輪先結束而沒等到結果的呼叫，會在歷史中補上一筆「可能沒有執行」的結果，核准不會延續到下一次要求。
  載入保存的歷史時也一樣補上。
- 保存的歷史若以沒有回應的核准請求結尾，載入時該呼叫視為拒絕。
- 要求核准的呼叫若沿用對話中用過的 call id，到達時就拒絕，也不寫進歷史：`FunctionInvokingChatClient` 以 id 辨識呼叫，
  會把舊的結果當成它的結果，或讓之後每次要求都失敗。卡片會說明原因，但模型不會被告知，所以該輪就此結束。若某個 provider
  每次回應都用同樣的編號（`call_0`），第一次之後的每個核准請求都會這樣被拒絕。
- 該輪等待使用者的時間不計入它的時間，進度列與摘要都一樣。

### 核准卡顯示什麼

使用者核准的就是工具會收到的內容，所以卡片以縮排 JSON 完整顯示參數。參數很長時在卡片內捲動，下方的提示說明還有內容。
不會畫出任何東西、或會改變周圍文字順序的字元（控制字元與格式字元，例如雙向覆寫字元與零寬字元）一律顯示為 `\u{202E}`
這類跳脫形式，套用在所有工具卡的參數、標題與結果。各種文字的字母照常顯示。

應用程式為 `ToolCallEntry` 註冊的樣板會取代這張卡片，這時完整顯示參數就是該樣板的責任。可以用
`ChatView.ApproveToolCallCommand` 與 `ChatView.RejectToolCallCommand` 決定呼叫。

### 在自己的迴圈裡核准

自己跑迴圈的應用程式照舊套用更新；`ToolApprovalRequestContent` 會把呼叫放進 `ChatTurn.PendingApprovals`。
`ChatTurn.WaitForApprovalsAsync` 等使用者決定完畢，回傳帶有決定的 user 訊息，應用程式在下一次要求時把它送給模型。使用者可能在串流還沒結束時就決定，所以串流結束後，只要
`ChatTurn.IsAwaitingApproval` 或 `ChatTurn.HasDecisionsToSend` 為 true，應用程式就要等待並取得決定。
`ChatTurn.Approve` 與 `ChatTurn.Reject` 可以從程式決定呼叫，例如自動核准使用者信任的工具。

### 某個工具的呼叫專用的樣板

`ToolCallTemplate` 以應用程式自己的樣板顯示它指名的工具的每一次呼叫，取代預設的工具卡，例如天氣工具用天氣卡。
註冊方式與任何資料樣板相同，放在 view 上，或往上到 Application 的任何一層：

```xml
<chat:ChatView.DataTemplates>
  <chat:ToolCallTemplate ToolName="get_weather">
    <DataTemplate x:DataType="pc:ToolCallEntry">
      <local:WeatherCard />
    </DataTemplate>
  </chat:ToolCallTemplate>
</chat:ChatView.DataTemplates>
```

- 名稱以 Ordinal 比對，先比中的樣板勝出。
- 使用這種樣板的呼叫，即使 `ChatView.ShowsActivity` 關閉也會顯示：自己畫卡片的工具本來就是要給人看的。其他為
  `ToolCallEntry` 註冊的樣板照舊依 `ShowsActivity` 決定。
- 等待核准的呼叫也套用該工具的樣板。樣板可以用 `ChatView.ApproveToolCallCommand` 與 `ChatView.RejectToolCallCommand`
  決定呼叫，這時向使用者完整呈現工具會收到的內容，就是樣板的責任。

呼叫的參數與結果通常是 JSON 元素。`ToolCallEntry.TryGetArgument` 與 `ToolCallEntry.TryGetResult` 用
`JsonTypeInfo<T>` 把它們讀成指定型別（本身就是該型別的值，或從 JSON 讀），在裁剪與 AOT 的應用程式裡也能用。

### 放應用程式自己內容的位置

三組屬性，命名方式與 `EmptyContent`、`EmptyContentTemplate` 相同：

| 屬性 | 位置 | 例如 |
|------|------|------|
| `HeaderContent` | 對話上方；對話捲動時它固定不動 | 標題、模型選單、清除對話的按鈕 |
| `PromptHeaderContent` | 輸入框上方，在輸入區之內 | 提問的主題、快速指令 |
| `PromptFooterContent` | 輸入框下方，在輸入區之內 | 「回答可能有誤」的提醒 |

內容為 `null` 時不佔空間；對應的 `…Template` 用來顯示不是控制項的資料。既有樣板部件的名稱不變，所以應用程式自訂的
控制項樣板仍可使用；要顯示新內容，得自己加上對應的 presenter。

### `ChatTurn.AddEntry`

自己跑迴圈的應用程式可以在回合進行中加入自己的項目，例如請使用者選答案的卡片。它之前的回覆會結束，之後到達的文字會開新的回覆，
該輪的摘要排在它後面。與其他自訂項目一樣，它會顯示，但不會送給模型，保存的歷史也不含它。回合中直接加進
`ChatConversation.Entries` 的項目不會結束回覆：之後到達的文字仍會接在它上方的回覆裡。請改用 `ChatTurn.AddEntry`。

## 行為變更

### 工具呼叫的兩個新狀態

`ToolCallStatus` 新增兩個值，加在既有值之後，既有值的數字不變：

- `AwaitingApproval`：呼叫正在等待使用者。
- `Rejected`：呼叫沒有執行，因為有人說不：使用者或應用程式。有提供原因時，`ToolCallEntry.RejectionReason` 說明原因。
  應用程式自己拒收呼叫時（例如工具不接受的參數），改設這個狀態，不要用 `Failed`。

該輪結束時仍在等待核准的呼叫是 `Canceled`。

**處理方式**：列舉所有值的 `ToolCallStatus` `switch` 會讓兩個新值落到 default 分支；請替它們加上自己的分支。
