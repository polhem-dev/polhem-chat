# Polhem.Chat 0.1.1 — 發佈說明

[English](../../en/changelogs/0.1.1.md)

本檔是 [CHANGELOG.zh-TW.md](../../../CHANGELOG.zh-TW.md) 中 `[0.1.1]` 條目的詳細內容。

這一版來自第一個改用這兩個套件的應用程式，它顯示出長時間、大量使用工具的對話需要什麼。對話現在只顯示寫給使用者的內容，
下方一行即時的進度行說明模型正在做什麼：在處理什麼、經過多久、第幾次要求、已經寫了多少 token。每一輪的摘要加上這一輪
發出的要求次數，以及輸入中的快取部分。另外，畫面在兩種過去會停止跟隨的情況下，現在會繼續跟著最新項目捲動。

沒有移除或變更任何公開成員。有兩個預設行為會改變對話的外觀。

各類應用程式要處理的事項：

- **依賴推理過程或工具呼叫以項目顯示的應用程式**：[推理過程與工具呼叫改在進度行顯示](#推理過程與工具呼叫改在進度行顯示)。
- **改寫過複製鈕外觀的應用程式**：[複製鈕改成圖示](#複製鈕改成圖示)。
- **自己跑迴圈、一輪會發出多次要求的應用程式**：在每次要求前呼叫 `ChatTurn.BeginCall`，次數才會被計算
  （[要求次數、快取 token 與經過時間](#要求次數快取-token-與經過時間)）。

## 新功能與變更

### 進度行

回合進行中，對話下方有一行顯示模型正在工作：動態圖示、目前在做什麼（「思考中…」或正在執行的工具標題）、經過時間
（「2 分 32 秒」）、第幾次要求，以及到目前為止回報的輸出 token。在第一段文字出現前，以及工具結果回來到下一次回應之間，
這一行會說明回覆正在路上。它跟著 `IsGenerating`，所以使用 `ChatRunner` 或自己跑迴圈的應用程式都適用。

`ChatView.ActivityIcon` 可以換成其他動態 GIF。套件自己解碼並播放 GIF，不多加任何依賴。`ChatViewStrings` 新增
`CallFormat`、`SecondsFormat`、`MinutesFormat`、`OutputTokensFormat` 字串。

### 要求次數、快取 token 與經過時間

每一輪的摘要在發出多次要求時列出要求次數，provider 回報快取時列出輸入 token 中的快取部分
（`UsageDetails.CachedInputTokenCount`），對應 `CallsFormat`、`CachedTokensFormat` 字串。只發出一次要求的一輪不顯示次數。

`ChatRunner` 依串流更新的 response id 自己計算每一輪的要求次數。自己跑迴圈的應用程式在每次要求前呼叫新的
`ChatTurn.BeginCall`。另新增 `ChatTurn.Calls`、`ChatTurn.Elapsed`、`TurnSummaryEntry.Calls`，以及
`ChatConversation.CurrentTurn` 與 `ChatTurn.Calls` 的變更通知。次數保存在歷史中，`LoadHistory` 會還原。

## 行為變更

### 推理過程與工具呼叫改在進度行顯示

模型的推理過程與工具呼叫不再以項目顯示。這些項目仍留在對話與歷史中，只是畫面不顯示。設定 `ChatView.ShowsActivity`，
或按進度行最後的 ›，可以再顯示它們。

想維持 0.1.0 外觀的應用程式，設定這個屬性：

```xml
<chat:ChatView ShowsActivity="True" />
```

### 複製鈕改成圖示

回覆的複製鈕改成小圖示，只在游標移到該則回覆上時出現，不再在每則回覆下方放一個有文字的按鈕。`ChatView.CopyCommand`
沒有變，所以替換回覆樣板的應用程式繫結同一個命令即可。

## 修正

- 上方的控制項把自己捲入可見範圍時（例如剛關閉的卡片中的按鈕把鍵盤焦點交出去），`ChatView` 不會再停止跟著最新項目捲動。
  現在只有使用者自己捲動（滾輪、捲軸、鍵盤、觸控）才會離開最下方（[#14](https://github.com/polhem-dev/polhem-chat/pull/14)）。
- `ChatView` 在變高的同時收到新項目時（例如一輪結束時它下方的一行消失），不會再停止跟著最新項目捲動。之前它把版面移動的
  捲動位置誤當成使用者往上捲，並顯示「回到最新」（[#14](https://github.com/polhem-dev/polhem-chat/pull/14)）。
